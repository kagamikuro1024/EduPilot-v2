## Findings

### F-1 — Medium — "Tài liệu chưa đề cập" bypasses k-anonymity: TEACHER/TA read one student's private-chat question verbatim

**Location**
- `backend-go/internal/insight/service.go:477` — `Uncovered: uncovered(d.items)`. No student-count threshold.
- `backend-go/internal/insight/service.go:619-643` — `uncovered()`. Each distinct `no_context` question becomes `{Text: trim(it.text), Count: 1}`. It never checks how many distinct students asked it.
- `backend-go/internal/insight/service.go:389-399` — `collect()` reads **private** chat (`InsightChatQuestions`, `store/queries/insight.sql:3-17`).
- `backend-go/internal/insight/service.go:296-300` — the Markdown export lists the same texts.
- `frontend/src/features/insights/KnowledgeGap.tsx:111-117` — the UI renders each text.
- Route guard: `backend-go/internal/httpapi/insighthttp/handler.go:29-31` — `auth.StaffRole`, so both TEACHER **and TA** pass.

**Evidence**
```go
// service.go:494-498 — topics enforce k ≥ 3 (FR-13) …
if c.sig.Students < MinStudents {
    t.FewAsked = true
} else {
    t.Examples = pickExamples(d.items, c.idx)
}
// service.go:619-631 — … but the uncovered list does not
for _, it := range items {
    if !it.noCtx { continue }
    ...
    cnt[k] = &Uncovered{Text: trim(it.text), Count: 1}
```
- `MinStudents = 3 // chủ đề < 3 sinh viên: không câu mẫu (k-ẩn danh, FR-13)` (service.go:38).
- The project invariant in `store/queries/escalation.sql:1-2` says staff read `chat_messages` **only** through `GetEscalatedExchange` / `ListTicketTranscript`. `InsightChatQuestions` is a third staff-facing read path.
- `no_context` is set for any RAG question with no hit (`agent/agent.go:249-250`). Off-topic personal questions therefore land in this list. Examples: sick leave, money, family.

**Exploit scenario**
1. A student asks the private AI chat a personal question that the course material does not cover. Example: "em bị ốm tuần sau có xin hoãn bài được không, em ở KTX khu B phòng 302".
2. The answer is marked `no_context`.
3. A TA of the class calls `POST /courses/{id}/insights/knowledge-gap/generate`, then `GET …/latest` or `…/export`.
4. The question appears verbatim with `count: 1`.
5. Roster redaction (`privacy.Detect`) and the `selfIntro` regex remove only roster names, MSSV and email, and only "em là …" self-introductions. Other identifying context stays. In a small class, a one-off question plus its timing often identifies the student.
6. Result: TEACHER/TA read the content of a student's private chat **without any escalation**. AGENTS.md forbids this.

The spec only allows anonymous examples with k ≥ 3 (SRS FEAT-p10-eval §NFR "câu mẫu k ≥ 3, ẩn danh"; FR-13). FR-14 ("from `no_context` questions") does not exempt this list from that rule.

**Suggested fix (smallest)**
- In `uncovered()`, collect distinct `it.student` per normalised key.
- Emit an entry only when it has `≥ MinStudents` distinct students.
- Keep `Count` as the total.
- Add one assert test: one student asking a no-context question 5 times gives an empty `uncovered`.

Optional, same change: on `GET latest/export`, drop stored reports whose source session was soft-deleted. Today, text collected before a student deletes the session stays in `insight_reports.payload` for good.

### F-2 — Low — `GET /api/v1/events` (SSE) skips the session-revocation check and the production `RequireSession` check

**Location**
- `backend-go/internal/httpapi/router.go:194-196` — `/events` is mounted outside the business group.
- `backend-go/internal/httpapi/sse/handler.go:103` — `auth.Middleware(d.Verifier)` is called with **no options**.

**Evidence**
```go
// sse/handler.go:103
return auth.Middleware(d.Verifier)(http.HandlerFunc(h.stream))
```
```go
// router.go:198-202 — the chat SSE right next to it DOES apply them
r.Use(auth.Middleware(d.Verifier, authOptions(d)...))
```
`authOptions` (`routes.go:207-216`) adds `auth.WithRevocation(d.Sessions)` and, in production, `auth.RequireSession()`. `HandlerDeps` has no field for either, so `/events` cannot get them.

**Exploit scenario**
1. An attacker obtains a user's access token (shared computer, leaked HAR).
2. The user logs out, changes their password, or an ADMIN disables the account. Every other API now returns `401 SESSION_REVOKED`.
3. `/events` still accepts the token and streams that user's notifications: ticket titles, job progress, `TICKET_NEW` for staff.
4. This continues until the JWT expires. Stream lifetime is capped at token expiry: `ACCESS_TOKEN_TTL`, default 15 min, configurable up to 1 h (`config.go:316`).
5. Dev tokens without `sid` are also accepted on this route in production.

Impact is limited by token lifetime. That is why this is Low.

**Suggested fix**
- Pass `authOptions(d)` into `sse.NewHandler`. For example, add `MW []auth.MiddlewareOption` to `HandlerDeps` and use `auth.Middleware(d.Verifier, d.MW...)`.
- Add a test: a revoked session gets 401 on `/events`.

## Checked, no issue found

- **`/admin/audit`** (`internal/audit/audit.go`, `audithttp`)
  - ADMIN-only through `RequireRole`.
  - Returns only top-level changed-field names, never `before`/`after` values.
  - The cursor is bound to a filter fingerprint, the span is capped at 90 days, and `limit` is validated.
  - Writes a `VIEW_LIST` audit row in the same transaction before returning.
- **Observability** (`internal/observability`, `observabilityhttp`)
  - `/admin/observability/*` is ADMIN-only. The per-course summary uses `Manage`.
  - The request table has no content.
  - `Open` requires a 10–200 character reason and writes `audit_log` before returning the masked prompt. If the audit write fails, nothing is returned.
- **Knowledge-gap report**, all parts except F-1
  - `StaffRole` guard and `Idempotency-Key` on generate.
  - Every query filters by `course_id`; `InsightReportGet` filters by `course_id` and `id`.
  - Text is anonymised before embedding and LLM calls. If redaction fails, the text is dropped (fail-closed).
  - The `samples` field is unexported, so it is never serialised.
  - Examples only appear at k ≥ 3.
- **Exam stats, 5 APIs** (`examhttp/analytics.go`, `exam/analytics.go`)
  - Course guard on 4 of them. `compare` is limited to the caller's own TEACHER courses (`ExamAnalyticsTeacherCourses(user)`).
  - Only `PUBLISHED` exams are counted. ADMIN gets totals only (`identity=false`).
  - `declining` is `StaffRole` only. No server-side caching.
- **Student `/assignments`**
  - `MemberRole` / `StudentRole` guards.
  - Unpublished assignments return 404 for students.
  - `StudentOf` strips the reference answer and guidance.
  - `mine` reads only `MinePublishedResult`.
- **Submission upload**
  - Presigned PUT signs the extension-derived content type, the length and the SHA-256.
  - The Redis ticket is bound to user, course and assignment.
  - Size is re-checked and content type is sniffed.
- **Document upload**
  - Content type is signed with `PresignPutSized`, the ticket is bound to user, course and purpose, and magic bytes are checked.
- **Auth and session**
  - Refresh token: `HttpOnly`, `Secure`, `SameSite=Lax` cookie, plus a `cookieGuard` CSRF check (Origin / Sec-Fetch-Site / JSON content type).
  - Verify, reset, invite and refresh tokens are stored only as SHA-256 hashes (`auth/tokens.go:42-46`, `session.go:326,411`).
  - IP rate limits on token endpoints. `register` and `resend` give the same message for every case.
  - Revocation is checked on every Bearer API in the business group (gap: F-2).
- **CORS**: exact-match allow-list, never `*`. **Client IP**: X-Forwarded-For is honoured only from `TRUSTED_PROXY_CIDRS`, and Caddy (no `trusted_proxies`) overwrites XFF.
- **Frontend**
  - Access token is held in memory only (`shared/data/tokenStore.ts`).
  - No token in localStorage or sessionStorage. localStorage holds only drafts and UI preferences.
  - Markdown renderer emits React nodes, not `dangerouslySetInnerHTML`.
  - Calendar, thread and today hrefs are built by the server.
- **ICS feed**
  - 32-byte random token, stored as a hash, per-IP limit.
  - The Caddy log filter redacts `token=`. The gateway access log records only `URL.Path`.
- **Chat private sessions**: owner-scoped (`GetChatSession{ID, UserID}`, `GetChatMessageOwned`). Non-students get 403.
- **Escalation staff reads**: only the escalated exchange and the ticket transcript.
- **LLM gateway**
  - A Masker is mandatory (`llm/mask.go:33-39`).
  - `NoMask` exists only in tests and the `testroutes` build.
  - A call with no course fails closed.
- **IMAP / Teams secrets**: encrypted, and write and test routes need Manage + ADMIN.
- **Logs**: no PII keys or values found in `slog` calls. Error logs carry the path only.
- **Secrets**: no API keys or private keys in tracked code (one fake `AIzaFAKE…` key in a QA doc). `.env` and `.env.local` are gitignored.
- **Attendance 10.8** (`dev-108`: `internal/attendance`, `attest`, `attendancehttp`)
  - QR token: HMAC-SHA256 per-window key, 80-bit MAC, `hmac.Equal`, step ∈ {s, s−1}.
  - Short code: constant-time compare, with per-student wrong-code counting and 429.
  - Device signature binds the token or code and the JWT `user_id`.
  - Key Attestation: chain to the embedded Google roots, revocation list, one-time nonce (`GetDel`), TEE/StrongBox level, package + signing-cert digest, leaf key equals the submitted key.
  - Every staff operation filters by `(course_id, id)`. Student identity comes only from the JWT.
  - Minor, not a vulnerability: the `v.fail(ctx, "<step>")` labels in `attest.go:146-162` are shifted by one step ("revoked?", "level", "challenge", "app"), which will mislead incident triage.
