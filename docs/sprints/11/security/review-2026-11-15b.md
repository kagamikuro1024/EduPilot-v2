## Findings

### F1 (Medium): Crisis messages go into the knowledge-gap corpus; their keywords and possibly full text reach the LLM, `insight_reports`, and TA/TEACHER screens
- **Where**
  - `backend-go/internal/store/queries/insight.sql:3-17` (`InsightChatQuestions`). It filters on role, date and active enrolment only. It has no `intent` filter on the reply `a`, and no crisis check on `u.content`.
  - `backend-go/internal/insight/service.go:391-401` (`collect`). Every row becomes an `item`.
  - `service.go:430-436`. All texts go to `LLM.Embed`, which is an external provider call through the gateway.
  - `service.go:467`. `Keywords(tx, 3)` runs on every cluster, including clusters asked by only 1 student.
  - `service.go:509`. The fallback name is built from those keywords.
  - `name.go:25`. The keywords of the top 8 topics go into the `Structured` prompt.
  - `pickExamples` / `uncovered`. They show the sentence verbatim once ≥ 3 students sent the same normalised crisis sentence.
- **What the project requires.** Crisis text may only live in `chat_messages.content`:
  - `chat/send.go:212-213` refuses to use it as a session title.
  - `chat/crisis_test.go:39-49` checks that the crisis canary appears in no other table.
  - US-P4-07 AC8: staff have no path to read it.
  - US-P3-04 AC13 / FEAT-p10-eval US AC6a: crisis text is never sent to any LLM.
- **Exploit / scenario.** No attacker is needed; normal use triggers it.
  1. A student sends "em không muốn sống nữa, bỏ học luôn" in private chat. The reply gets `intent='CRISIS'`.
  2. A TA clicks «Tạo báo cáo» (`POST /courses/{id}/insights/knowledge-gap/generate`, StaffRole).
  3. The worker embeds the sentence through the external provider. It clusters the sentence alone, so `few_asked=true` and the topic has no examples.
  4. Keywords such as `["song","nua","hoc"]` are stored in `insight_reports.payload.topics[].keywords` and used as `name` (or sent to the naming LLM).
  5. The TA sees them in `/insights` and in the Markdown export.
  6. If 3 students type the same crisis sentence (short phrases like "em muốn chết quá" are plausible), the sentence appears verbatim under «Câu mẫu» or «Tài liệu chưa đề cập».
- **Evidence.** The query has no `intent` predicate. `collect` has no `agent.DetectIntent` check. `guardLeaks` (`service.go` end) checks only `name/why/recommendation` against below-threshold sentences; it never checks crisis content or `keywords`.
- **Fix.**
  1. In `collect`, drop any row where `agent.DetectIntent(r.Content) == agent.IntentCrisis`. This is the same deterministic check `chat/send.go` uses, and it also covers the case where no assistant row has been written yet.
  2. Defence in depth: add `and (a.intent is distinct from 'CRISIS')` to `InsightChatQuestions`.
  3. Apply the same filter to `InsightThreadQuestions`. Threads are already blocked by the crisis precheck, but the filter is cheap.
  4. Add a test: a crisis canary sent in chat must be absent from `insight_reports.payload::text` and from fake-LLM `Embed` / `Structured` payloads.

### F2 (Low): Fixes P-11-31/32 apply only to new reports; old reports are still served unguarded by `/latest`, the "reused" path and `/export`
- **Where**
  - `backend-go/internal/insight/service.go:117-119`. `Generate` returns the old report (`Reused`) when there is no new data, so the fixed pipeline never runs.
  - `service.go:224-262`. `Latest` returns the stored payload as-is, plus `Diff` names from the previous report.
  - `service.go:266-281`. `Export` renders `markdown(rep)` from the stored payload without `guardLeaks`.
  - No migration deletes old `insight_reports` (checked `db/migrations/00015_observation.sql`; nothing else touches the table).
- **Spec.** FR-29 (FEAT-p10-eval SRS:128) says the guard runs "trước lưu **và trước `export`**". Today it only runs before save (`service.go:338`).
- **Scenario.** Any stack with a knowledge-gap report generated before P-11-31/32 still has:
  - `examples` and `uncovered[].text` taken from a single student's private chat;
  - LLM names built from that input.

  A TA/TEACHER keeps reading them through `GET …/knowledge-gap/latest` and `GET …/{rid}/export` (any old `rid` of the course). Pressing «Tạo báo cáo» does not replace the report while the watermark is unchanged.
- **Fix (pick one).**
  - Add `payload.schema` (or `kind_version`) set to 2 by the fixed generator. Treat older payloads as missing: 404 on latest and export, and no reuse in `Generate`.
  - Or ship a one-off migration that deletes `insight_reports` created before the fix.

  Re-running `guardLeaks` at read time does not work, because `below` is not persisted.

## Checked, no issue found
- **Exam analytics, 5 APIs** (`httpapi/examhttp/analytics.go`, `exam/analytics.go`, `store/queries/exam_analytics.sql`)
  - Routes are mounted inside the `auth.Middleware` group (`examhttp/results.go:32` → `routes.go` group).
  - overview/trend: `StaffOrAdmin`; ADMIN gets `identity=false`, so mean/median/distribution are null. hard-items/declining: `StaffRole` (ADMIN refused). compare: `RequireRole(TEACHER)`, with the course list taken from the JWT `sub` and ACTIVE TEACHER enrolments only.
  - Every query is filtered by `course_id` and PUBLISHED/GRADED.
  - `exam_ids` is built server-side from the course's own exams. A foreign `exam_id` gives 404.
  - Cursors are parameterised and limit is 1–100.
  - Declining joins on `user_id`; `student_code_snapshot` is display only (no MSSV linking).
  - `Cache-Control: private, no-cache`.
- **`/admin/audit` (US-P10-14)** (`httpapi/audithttp/handler.go`, `audit/audit.go`, `queries/audit.sql`)
  - `RequireRole(ADMIN)` reads the role from the JWT.
  - Entity is checked against a regex, actor is parsed as a UUID, and the span is limited to 90 days.
  - The cursor holds `v`, `t`, `i` and a fingerprint of the normalised `(entity, actor, from, to)`. A mismatch gives 422.
  - The read and the `VIEW_LIST` insert run in one transaction. If the insert fails, nothing is returned. Commit happens before the response.
  - SQL returns only top-level keys (`jsonb_object_keys`), never values.
  - I sampled all `InsertAuditLog` callers: keys are fixed names, not data-derived. `Cache-Control: no-store`.
  - The UI (`features/admin/AdminAudit.tsx`) renders text only.
- **Knowledge-gap fixes P-11-31/32/32b**
  - `uncovered` and `pickExamples` count distinct students per `textfold.Collapse` sentence, with k ≥ 3.
  - `samples` = qualified examples only (`service.go:510`).
  - `guardLeaks` covers name/why/recommendation (6-gram, plus whole sentences of 4–5 words) before save.
  - Accepted by spec (FR-13/FR-29), not reported: topics asked by < 3 students still show cluster keywords and a keyword-based name.
- **SSE `/events`** (`httpapi/router.go:193-196`, `httpapi/sse/handler.go:96`)
  - Now wrapped in `auth.Middleware(d.Verifier, authOptions(d)...)`, which adds revocation and `RequireSession` in production.
  - Stream lifetime = min(`SSE_MAX_DURATION` 120 s, token expiry), so a revoked session keeps a stream open for at most about 2 minutes.
- **Early session refresh U1** (`shared/data/earlyRefresh.ts`, `authSession.ts`, `app/layout.tsx`, `AuthProvider.tsx`)
  - The access token stays in memory (`tokenStore`).
  - localStorage holds only the `ep_returning` flag.
  - The early promise is taken once and deleted from `window`.
  - The same `ep-refresh` Web Lock is used in both places, and the lock is released only after the response arrives (cookie rotated). No deadlock: the early lock request is queued first.
  - The `epoch` check stops a stale refresh from overwriting a newer session.
  - CSP `'unsafe-inline'` predates this work (10.8, per `docs/sprints/11/handoff/dev-wave3.md:38`).
- **`seed/demo/fake_llm.json` and its loader** (`llm/fake/fake.go:408-460`)
  - Startup refuses `LLM_DEMO_FILE` when `APP_ENV=production` (`platform/config/config.go:441-443`).
  - Recordings contain no secrets or real PII.
  - Grading recordings match on prompt sentences, so canned grades can be triggered by text in a submission, but only on demo stacks.
  - Personal data in chat D1 still comes from JWT-scoped tools, not from the recording.
- **Seed** (`scripts/seed.mjs`)
  - Production is blocked before any I/O (`:46-52`).
  - The password comes from the environment and is masked in logs.
  - The new `EP_PORT_MOCK_IMAP/GRAPH` variables only change localhost ports.
