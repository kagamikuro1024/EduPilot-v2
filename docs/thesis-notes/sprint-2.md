# Sprint 2 — ghi cho luận văn (PG Nền Go)

- **Gateway không trạng thái ngay từ đầu (D22)**: rate limit, Idempotency-Key, đếm kết nối SSE đều ở Redis; file qua MinIO + URL ký sẵn; image `readonly rootfs`, không shell, người dùng `nonroot`. Chứng minh bằng `--scale gateway=2` sau Caddy: 40 request chia 19/21 hai bản; tắt một bản giữa 200 request chỉ 1 lỗi.
- **Số liệu nền bản Go** (`benchmarks/reports/pg-baseline.md`): RAM nghỉ gateway ≈ 4 MiB, worker ≈ 5 MiB; khởi động 9–69 ms; image gateway 9,4 MB, worker 8,9 MB (ngưỡng 40 MB); k6 smoke p95 `healthz` 5,75 ms, `readyz` 6,92 ms, `jobs/{id}` qua PgBouncer 8,57 ms, 0 % lỗi — so với hệ cũ 6 runtime trong một container (`legacy-perf.md`).
- **Quy ước API dùng chung** (mọi phase sau kế thừa): lỗi `{code,message,details,retry_after}`, phân trang con trỏ `(created_at,id)` không OFFSET, Idempotency-Key 24 h (gửi đôi → một bản ghi, response y hệt), khoá lạc quan `version` → 409, ETag, việc dài `202 + job` + SSE `job.progress`, outbox cùng transaction + consumer retry 3 lần / dead-letter.
- **SSE nhiều bản gateway**: fan-out qua Redis pub/sub, `Last-Event-ID` đọc bù từ bộ đệm 1 giờ; id vượt bộ đệm → sự kiện `resync` để client nạp lại trạng thái (góp ý #13).
- **Hợp đồng là nguồn sự thật**: `api/openapi.yaml` (3.1) + `internal/contract` kiểm response thật bằng `kin-openapi` (D52, chỉ trong test, depguard chặn khỏi binary); route thử tách bằng build tag `testroutes` thay vì biến môi trường (góp ý #1 — an toàn mặc định).
- **Khó khăn thật tìm ra khi chạy cổng**: PgBouncer giữ cache NXDOMAIN 15 s làm hồi phục sau khi Postgres khởi động lại chậm 11–19 s; Caddy `unhealthy_status 503` nuốt 503 hợp lệ của ứng dụng; vai Research kiểm chứng 4 rủi ro hạ tầng bằng PoC trước khi dev đụng tới (kin-openapi 3.1, pgx transaction mode, Caddy SSE, testcontainers trên colima).
