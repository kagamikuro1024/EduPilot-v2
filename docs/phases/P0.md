# P0 — Chuẩn bị

| Ước lượng | Phụ thuộc | Nhánh |
| --- | --- | --- |
| 0,5 tuần | – | `feat/p0-prep` |

**Mục tiêu:** có lưới an toàn trước khi đụng vào code: CI, mail giả lập, và bản ghi đầy đủ hành vi của gateway Java để làm đặc tả cho việc port.

Ngoài phạm vi: viết bất kỳ dòng Go nào; sửa hành vi hệ thống.

## Lát việc (mỗi lát một phiên Claude Code)

**L1. CI + MailHog**
- [ ] GitHub Actions `ci.yml`: `pytest -q`, `mvn -q test` (tạm, đến hết PG), `pnpm -C frontend lint && build`
- [ ] Thêm MailHog vào `docker-compose.local.yml` (SMTP 1025, UI 8025)
- [ ] `pnpm dev` vẫn dựng đủ stack

**L2. Ghi hợp đồng API**
- [ ] Đọc 16 controller trong `backend-java/.../controller/` → viết `backend-go/api/openapi.yaml` (tạo trước thư mục) gồm đường dẫn, method, quyền, request/response, mã lỗi
- [ ] Ghi riêng định dạng SSE của chat stream: tên sự kiện, payload từng loại, sự kiện kết thúc, sự kiện lỗi
- [ ] Ghi claims và thời hạn JWT, thuật toán ký, định dạng hash mật khẩu

**L3. Golden response**
- [ ] Script `scripts/record-golden.mjs`: đăng nhập 3 vai trò, gọi mọi endpoint trong openapi với DB seed hiện có, lưu `{request, status, body}` vào `backend-go/testdata/golden/`
- [ ] Danh sách trường bỏ qua khi so sánh (id ngẫu nhiên, thời gian) trong `golden/ignore.json`
- [ ] Ghi một phiên SSE mẫu (dùng provider giả ở Python để ổn định)

**L0. Kịch bản demo là kim chỉ nam** (viết TRƯỚC khi code)
- [ ] `docs/DEMO_SCRIPT.md`: kịch bản 15 phút cho buổi bảo vệ, đi qua các luồng F2 → F3 → F5 → F7 → F9 → F10 → F17 bằng 2 lớp seed. Mỗi phase sau phải làm cho ít nhất một bước của kịch bản chạy thật; cuối mỗi phase chạy lại kịch bản tới bước xa nhất có thể
- [ ] Ghi rõ phương án dự phòng cho ngày bảo vệ: chế độ `DEMO_MODE=true` dùng provider `fake` trả lời đã ghi sẵn cho đúng các câu trong kịch bản (mạng hay API hỏng vẫn demo được) + video quay sẵn

**L4. Mốc so sánh**
- [ ] Khung k6 ở `benchmarks/load/`: kịch bản `smoke.js` (đăng nhập, danh sách thread, một phiên SSE với provider giả) chạy vào gateway Java → `benchmarks/reports/load-baseline.json` (p95, lỗi). Đây là mốc để so với Go
- [ ] Chạy golden set RAG hiện có → `benchmarks/reports/baseline.json`
- [ ] Đo RAM nghỉ, thời gian khởi động, kích thước image của `java-backend` → `benchmarks/reports/port.md` (cột Java)

## Cổng nghiệm thu
```bash
pnpm dev && pnpm dev:status            # mọi container healthy, MailHog ở :8025
gh run list --limit 1                   # CI xanh
test -s backend-go/api/openapi.yaml
ls backend-go/testdata/golden | wc -l   # ≥ số endpoint trong openapi
test -s benchmarks/reports/baseline.json
```

## Bạn tự kiểm
- Mở `openapi.yaml`, đối chiếu ngẫu nhiên 5 endpoint với frontend `services/` xem có thiếu cái nào frontend đang gọi.
- Mở 3 file golden bất kỳ: có dữ liệu thật, không phải lỗi 401.

## Ghi cho luận văn
Số endpoint, số file Java, số dòng code Java (`cloc backend-java`) — dùng cho phần "quy mô port".
