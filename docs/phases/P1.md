# P1 — LLM Gateway + cấu hình provider (M12)

| Ước lượng | Phụ thuộc | Nhánh |
| --- | --- | --- |
| 1,5 tuần | PG, PU | `feat/p1-llm-gateway` |

**Mục tiêu:** không còn chỗ nào gọi thẳng OpenAI; đổi provider/model theo tác vụ trên UI mà không khởi động lại.

## Lát việc

**L1. Gateway Python**
- [ ] `src/llm/gateway.py`: `chat`, `stream`, `structured(json_schema)`, `embed`; tham số `task`; dùng LiteLLM
- [ ] Map lỗi 429 / timeout / auth về một kiểu chung để logic retry (tenacity) hiện có không đổi
- [ ] Chuỗi fallback theo `llm_task_routes.fallback_order`
- [ ] Ghi `llm_audit` mỗi lời gọi, kèm `trace_id` OpenTelemetry

**L1b. LLM Scheduler** (đọc `SYSTEM_DESIGN.md` mục 3.1 — đây là thành phần quyết định hệ thống có chịu được tải hay không)
- [ ] `src/llm/scheduler.py`: ba làn `INTERACTIVE` / `NEAR_REALTIME` / `BATCH`; mỗi `task` ánh xạ cố định vào một làn
- [ ] Token bucket RPM + TPM theo model (số liệu từ `llm_models`), trạng thái trên Redis để nhiều bản Python dùng chung; semaphore `LLM_MAX_CONCURRENCY`
- [ ] Làn BATCH tối đa `LLM_BATCH_SHARE` hạn mức khi làn INTERACTIVE có việc chờ
- [ ] Hàng chờ INTERACTIVE giới hạn `LLM_QUEUE_MAX`; đầy → lỗi `OVERLOADED` kèm `retry_after` ước tính (gateway trả 503)
- [ ] Cầu dao theo provider (mở 30 s sau N lỗi/429 liên tiếp) → fallback; retry backoff luỹ thừa + jitter
- [ ] Deadline từ metadata gRPC; client huỷ → huỷ lời gọi provider
- [ ] Suy giảm: mọi provider chết → trả lời trích xuất từ chunk + cờ `degraded=true`
- [ ] Khử trùng yêu cầu giống hệt đang bay (single-flight theo hash prompt) cho làn không cá nhân
- [ ] **Trần ngân sách** (`llm_budgets`, theo ngày / tháng, toàn hệ thống và theo lớp): bộ đếm chi phí trên Redis cập nhật sau mỗi lời gọi; 80% → sự kiện cảnh báo; 100% → làn BATCH ngừng nhận việc mới (việc nằm lại hàng đợi), làn INTERACTIVE chuyển sang model rẻ nhất đã cấu hình; không bao giờ tắt chat trong im lặng
- [ ] Provider giả `fake` có độ trễ và tỷ lệ lỗi cấu hình được — dùng cho test tải và CI

**L2. Thay thế lời gọi cũ**
- [ ] `agent.py`, `tools.py`, `guardrails.py`, `grpc_server.py`, `main.py`, `data_pipeline/pipeline/embedding.py`, `workers/analytics_worker.py`
- [ ] Sửa các test đang monkeypatch `AsyncOpenAI` sang provider giả của gateway
- [ ] Embedding: khoá 1536 chiều; từ chối model khác chiều

**L3. Cấu hình phía Go**
- [ ] Migration llm_config; `internal/llmconfig` CRUD; AES-GCM (`platform/crypto`); key chỉ ghi, trả về dạng che
- [ ] `POST …/test` → gRPC `AIAdminService.TestProvider`
- [ ] Sau khi lưu: publish `llm.config.changed`; Python subscribe và nạp lại; biến môi trường cũ làm dự phòng khi bảng trống

**L4. Frontend**
- [ ] `/settings/llm` (`design/DESIGN.md` §14.23, `LLMRouteTable`): bốn phần theo thứ tự — kết nối provider, bảng gán tác vụ, chuỗi fallback, cấu hình embedding tách riêng vì đổi là phải re-index; key chỉ ghi, sau khi lưu chỉ hiện trạng thái đã kết nối; trường nâng cao nằm sau `Cài đặt nâng cao`; nút Test là hành động phụ trên từng dòng; bảng usage (token, chi phí ước tính, độ trễ, lỗi theo tác vụ)

## Bạn tự kiểm
- Thêm 2 provider thật, đổi CHAT giữa hai cái, chat ngay sau đó; xem `llm_audit` ghi đúng provider.
- Nhập key sai → nút Test báo lỗi rõ; key không bao giờ hiện lại trên UI hay trong log.
- Tắt provider chính → fallback chạy.
- Bơm 200 việc BATCH giả rồi chat: chữ đầu tiên vẫn ra trong SLO.
- Tắt hết provider: chat trả lời kiểu trích xuất kèm nhãn "AI tạm thời không khả dụng", không treo.
